# 사용자 관리 기능 구현 계획 (Authelia 기반)

본 계획은 사용자관리 요구사항(역할·접근제어, 소셜 인증, 프로파일/키·인증서, 유료 구독)을 현재 인프라(Cloudflared + NPM + Authelia + FastAPI + Nuxt) 위에 단계적으로 구현하기 위한 실행 문서입니다.

## 1. 아키텍처 개요

역할 분리 원칙: 인증은 IdP(Authelia/소셜)에서, 인가는 백엔드에서 강제, 프록시는 경로별 보호.

- 인증(IdP): Authelia(OIDC/2FA/소셜), 필요 시 oauth2-proxy/Keycloak 대체 가능
- 인가(RBAC): FastAPI에서 `X-Forwarded-User/Groups` 기반 역할 도출 및 가드
- 프록시: NPM Forward Auth로 경로 보호(/knowledge-base, /api/v1/knowledge-base/*)
- 프로필/구독/키: 백엔드 DB + Vault/KMS 경유 저장

## 2. 접근제어 정책(요약)
- 커리큘럼(`/textbook`)은 일반회원 열람 허용(bypass)
- 지식베이스 화면(`/knowledge-base*`)과 관련 API(`/api/v1/knowledge-base/*`)는 관리자만(one_factor)
- Authelia access_control과 NPM Forward Auth(경로 한정) + FastAPI RBAC를 3중으로 적용

## 3. 소셜 인증(Google) 통합
- 1단계: oauth2-proxy 또는 Authelia OIDC로 Google 로그인 연결(Forward Auth)
- 첫 로그인 JIT(Just-In-Time) 프로비저닝: `/api/v1/users/me`에서 DB upsert + `last_login_at`
- 그룹→역할 매핑: admins→admin, tutors→tutor, users→student (헤더 우선)

## 4. 사용자 프로파일/키·인증서
- 테이블: `user_profiles`, `user_keys`, `user_certs`, 모두 `user_email` 기준
- 민감값은 Vault/KMS 경유 암호화 저장, DB에는 지문/경로만
- API: `POST/GET/DELETE /api/v1/profile/credentials`, `POST revoke`

## 5. 구독 관리(Stripe)
- 플랜: Free/Pro/Enterprise → 동시 작업수·AI한도와 연결
- API: `POST /api/v1/billing/checkout`, `GET /api/v1/billing/portal`, `POST /api/v1/billing/webhook`, `GET /api/v1/users/me/subscription`
- Webhook으로 상태 동기화, `require_subscription()` 가드로 기능 제한

## 6. 데이터 모델/마이그레이션
- users(email PK), user_profiles(user_id FK), user_keys, user_certs, subscriptions
- Alembic 마이그레이션 1팩으로 제공

## 7. 테스트 전략
- 단위: RBAC 가드(student/tutor/admin), 구독 한도, 키 지문 계산
- 통합: Forward Auth 헤더 모킹, 보호 경로 200/302/403 검증
- E2E: 로그인→역할별 화면, 결제→Webhook→권한 반영, 키 등록/폐기

## 8. 운영 자동화(MCP)
- SequentialThinking MCP
  - 온보딩: 사용자 등록→그룹 부여→초대→첫 로그인 감지→DB upsert→알림
  - 역할 변경: 그룹 업데이트→RBAC 드리프트 동기화→감사로그→롤백
  - 키 회전: 신규 키 수집→Vault 저장→지문 갱신→구 키 revoke
  - 결제 실패: Webhook 이벤트→Grace Period→자동 일시중지/복구
- Magic MCP
  - PR 자동화: Authelia/NPM/백엔드 설정 변경 PR, 정책 문서/역할표 생성
