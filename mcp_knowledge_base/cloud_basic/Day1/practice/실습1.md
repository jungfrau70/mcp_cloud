# 🎯 Azure FinOps 실습 시나리오 가이드 (웹콘솔 + CLI)

## 📋 개요

**목적**: Azure 환경에서 역할(재무팀, IT 관리자, IT 엔지니어)에 따라 리소스 사용/관리 및 비용 모니터링을 경험
**범위**: 
- Azure Entra ID (조직/사용자/역할 관리)
- Azure 리소스 계층 구조 (테넌트 → 관리 그룹 → 구독 → 리소스 그룹 → 리소스)
- Azure Storage (Blob Storage)
- Azure Cost Management + Billing (FinOps 관점)

## 🏗️ 1단계: Azure 환경 준비

### 1.1 Azure 계정 생성 및 구독 설정

#### 🌐 웹콘솔 방식
```markdown
1. [Azure Portal](https://portal.azure.com) 접속
2. "무료 계정 만들기" 클릭
3. Microsoft 계정으로 로그인
4. 개인 정보 입력 및 전화번호 인증
5. 신용카드 정보 등록 (무료 크레딧 사용)
6. 구독 생성: "Azure subscription 1" (기본)
```

#### 💻 CLI 방식
```bash
# Azure CLI 설치 (Windows)
winget install Microsoft.AzureCLI

# Azure CLI 설치 (macOS)
brew install azure-cli

# Azure CLI 설치 (Ubuntu)
curl -sL https://aka.ms/InstallAzureCLIDeb | sudo bash

# 로그인
az login

# 구독 확인
az account list --output table

# 구독 설정 (여러 개인 경우)
az account set --subscription "Azure subscription 1"
```

### 1.2 관리 그룹 생성

#### 🌐 웹콘솔 방식
```markdown
1. Azure Portal → "관리 그룹" 검색
2. "관리 그룹" 클릭
3. "+ 관리 그룹" 클릭
4. 관리 그룹 ID: "MG-Company"
5. 표시 이름: "Company Management Group"
6. "만들기" 클릭
```

#### 💻 CLI 방식
```bash
# 관리 그룹 생성
az account management-group create --name "MG-Company" --display-name "Company Management Group"

# 관리 그룹에 구독 연결
az account management-group subscription add --name "MG-Company" --subscription "Azure subscription 1"

# 관리 그룹 확인
az account management-group list --output table
```

## 👥 2단계: Entra ID 사용자 및 역할 생성

### 2.1 사용자 계정 생성

#### 🌐 웹콘솔 방식
```markdown
1. Azure Portal → "Azure Active Directory" 검색
2. "사용자" → "새 사용자" 클릭
3. 다음 사용자들 생성:
   - finance_user@contoso.onmicrosoft.com
   - itadmin_user@contoso.onmicrosoft.com  
   - engineer_user@contoso.onmicrosoft.com
4. 각 사용자에 임시 비밀번호 설정
5. "만들기" 클릭
```

#### 💻 CLI 방식
```bash
# 사용자 생성
az ad user create --display-name "Finance User" --user-principal-name "finance_user@contoso.onmicrosoft.com" --password "TempPass123!" --force-change-password-next-login true

az ad user create --display-name "IT Admin User" --user-principal-name "itadmin_user@contoso.onmicrosoft.com" --password "TempPass123!" --force-change-password-next-login true

az ad user create --display-name "IT Engineer User" --user-principal-name "engineer_user@contoso.onmicrosoft.com" --password "TempPass123!" --force-change-password-next-login true

# 사용자 목록 확인
az ad user list --output table
```

### 2.2 역할 할당

#### 🌐 웹콘솔 방식
```markdown
1. Azure Portal → "구독" → 구독 선택
2. "액세스 제어(IAM)" → "역할 할당 추가"
3. 재무팀 사용자에게 "Cost Management Reader" 역할 할당
4. 리소스 그룹 → "액세스 제어(IAM)" → "역할 할당 추가"
5. IT 관리자에게 "Contributor" 역할 할당
```

#### 💻 CLI 방식
```bash
# 구독 ID 확인
SUBSCRIPTION_ID=$(az account show --query id -o tsv)

# 재무팀 사용자에게 Cost Management Reader 역할 할당 (구독 단위)
az role assignment create --assignee "finance_user@contoso.onmicrosoft.com" --role "Cost Management Reader" --scope "/subscriptions/$SUBSCRIPTION_ID"

# IT 관리자에게 Contributor 역할 할당 (구독 단위)
az role assignment create --assignee "itadmin_user@contoso.onmicrosoft.com" --role "Contributor" --scope "/subscriptions/$SUBSCRIPTION_ID"

# 역할 할당 확인
az role assignment list --assignee "finance_user@contoso.onmicrosoft.com" --output table
az role assignment list --assignee "itadmin_user@contoso.onmicrosoft.com" --output table
```

### 3.3 Blob 컨테이너 생성 및 권한 설정

#### 🌐 웹콘솔 방식
```markdown
1. 스토리지 계정 → "컨테이너" 클릭
2. "+ 컨테이너" 클릭
3. 이름: "finops-data"
4. 공용 액세스 수준: "Private"
5. "만들기" 클릭
6. "액세스 제어(IAM)" → "역할 할당 추가"
7. IT 엔지니어에게 "Storage Blob Data Contributor" 역할 할당
```

#### 💻 CLI 방식
```bash
# Blob 컨테이너 생성
az storage container create \
  --name "finops-data" \
  --account-name "finopsstorage123" \
  --auth-mode login

# IT 엔지니어에게 Storage Blob Data Contributor 역할 할당
az role assignment create \
  --assignee "engineer_user@contoso.onmicrosoft.com" \
  --role "Storage Blob Data Contributor" \
  --scope "/subscriptions/$SUBSCRIPTION_ID/resourceGroups/RG-FinOps-Demo/providers/Microsoft.Storage/storageAccounts/finopsstorage123"

# 컨테이너 확인
az storage container list --account-name "finopsstorage123" --auth-mode login
```

## 🔒 4단계: 리소스 잠금 및 정책 설정

### 4.1 리소스 잠금 설정

#### 🌐 웹콘솔 방식
```markdown
1. 리소스 그룹 "RG-FinOps-Demo" 클릭
2. "잠금" 클릭
3. "+ 추가" 클릭
4. 잠금 이름: "CanNotDelete"
5. 잠금 유형: "삭제" 선택
6. "확인" 클릭
```

#### 💻 CLI 방식
```bash
# 리소스 그룹에 삭제 잠금 설정
az lock create \
  --name "CanNotDelete" \
  --resource-group "RG-FinOps-Demo" \
  --lock-type "CanNotDelete"

# 잠금 확인
az lock list --resource-group "RG-FinOps-Demo" --output table
```

### 4.2 Azure Policy 설정 (지역 제한)

#### 🌐 웹콘솔 방식
```markdown
1. Azure Portal → "정책" 검색
2. "정책 정의" → "정책 정의 만들기" 클릭
3. 정책 이름: "Allowed Locations"
4. 설명: "한국 리전만 허용"
5. 정책 규칙 작성 (JSON)
6. "저장" 클릭
7. "정책 할당" → 구독에 할당
```

#### 💻 CLI 방식
```bash
# 정책 정의 JSON 파일 생성
cat > allowed-locations-policy.json << 'EOF'
{
  "if": {
    "not": {
      "field": "location",
      "in": ["koreacentral", "koreasouth"]
    }
  },
  "then": {
    "effect": "deny"
  }
}
EOF

# 정책 정의 생성
az policy definition create \
  --name "AllowedLocations" \
  --display-name "Allowed Locations" \
  --description "한국 리전만 허용" \
  --rules allowed-locations-policy.json \
  --mode All

# 정책 할당
az policy assignment create \
  --name "AllowedLocationsAssignment" \
  --display-name "Allowed Locations Assignment" \
  --policy-definition "AllowedLocations" \
  --scope "/subscriptions/$SUBSCRIPTION_ID"

# 정책 확인
az policy assignment list --scope "/subscriptions/$SUBSCRIPTION_ID" --output table
```

## 💰 5단계: FinOps 비용 관리

### 5.1 비용 분석 (재무팀 역할)

#### 🌐 웹콘솔 방식
```markdown
1. 재무팀 사용자로 로그인
2. Azure Portal → "Cost Management + Billing" 검색
3. "Cost analysis" 클릭
4. 기간: "이번 달"
5. 그룹화 기준: "리소스 그룹"
6. 비용 대시보드 확인
```

#### 💻 CLI 방식
```bash
# 재무팀 사용자로 로그인 (브라우저 인증)
az login --username "finance_user@contoso.onmicrosoft.com"

# 비용 분석 (최근 30일)
az consumption usage list \
  --start-date $(date -d "30 days ago" +%Y-%m-%d) \
  --end-date $(date +%Y-%m-%d) \
  --output table

# 리소스 그룹별 비용
az consumption usage list \
  --start-date $(date -d "30 days ago" +%Y-%m-%d) \
  --end-date $(date +%Y-%m-%d) \
  --query "[].{ResourceGroup:instanceName, Cost:pretaxCost, Currency:currency}" \
  --output table
```

### 5.2 예산 설정

#### 🌐 웹콘솔 방식
```markdown
1. "Cost Management + Billing" → "Budgets" 클릭
2. "+ 추가" 클릭
3. 예산 이름: "MonthlyBudget"
4. 예산 금액: $100
5. 기간: "월별"
6. 알림 조건: 80%, 100%, 120%
7. "만들기" 클릭
```

#### 💻 CLI 방식
```bash
# 예산 JSON 파일 생성
cat > budget.json << 'EOF'
{
  "amount": 100,
  "timeGrain": "Monthly",
  "timePeriod": {
    "startDate": "2024-01-01T00:00:00Z",
    "endDate": "2024-12-31T23:59:59Z"
  },
  "notifications": {
    "Actual_GreaterThan_80_Percent": {
      "enabled": true,
      "operator": "GreaterThan",
      "threshold": 80,
      "contactEmails": ["finance_user@contoso.onmicrosoft.com"]
    }
  }
}
EOF

# 예산 생성
az consumption budget create \
  --budget-name "MonthlyBudget" \
  --resource-group "RG-FinOps-Demo" \
  --amount 100 \
  --time-grain "Monthly" \
  --start-date "2024-01-01" \
  --end-date "2024-12-31" \
  --notifications '{"Actual_GreaterThan_80_Percent":{"enabled":true,"operator":"GreaterThan","threshold":80,"contactEmails":["finance_user@contoso.onmicrosoft.com"]}}'
```

## 🧪 6단계: 역할별 테스트

### 6.1 IT 엔지니어 테스트 (Blob 업로드)

#### 🌐 웹콘솔 방식
```markdown
1. IT 엔지니어 사용자로 로그인
2. 스토리지 계정 → "컨테이너" → "finops-data" 클릭
3. "업로드" 클릭
4. 테스트 파일 업로드
5. 리소스 그룹 삭제 시도 → 실패 확인 (잠금)
```

#### 💻 CLI 방식
```bash
# IT 엔지니어로 로그인
az login --username "engineer_user@contoso.onmicrosoft.com"

# 테스트 파일 생성
echo "This is a test file for FinOps demo" > test-file.txt

# Blob 업로드
az storage blob upload \
  --account-name "finopsstorage123" \
  --container-name "finops-data" \
  --name "test-file.txt" \
  --file "test-file.txt" \
  --auth-mode login

# 업로드된 파일 확인
az storage blob list \
  --account-name "finopsstorage123" \
  --container-name "finops-data" \
  --auth-mode login \
  --output table

# 리소스 그룹 삭제 시도 (실패해야 함)
az group delete --name "RG-FinOps-Demo" --yes
# ❌ 실패: 잠금 때문에 삭제 불가
```

### 재무팀

- 제한된 권한 내에서 실제 리소스 생성 및 운영 수행
- 리소스 잠금, 정책 등 제약을 실습하며 **거버넌스 효과 체감**

## 💡 추가 학습 아이디어

1. **Budget 설정**: 구독 단위 예산(Budget)을 설정하고, 초과 예상 시 이메일 알림을 발송
2. **Tagging 기반 비용 분석**: `Project`, `Department`, `Owner` 태그를 필수로 지정 → Cost Management에서 태그별 비용 분석
3. **Azure Advisor**: 사용하지 않는 리소스, 과도한 스펙 VM 권장사항 확인
4. **리소스 잠금(Resource Lock)**: IT 엔지니어는 리소스를 **추가(Create)** 할 수는 있지만, **삭제(Delete)** 는 불가능하게 `CanNotDelete` 락 적용
5. **배포 지역 제한 정책 (Azure Policy)**: VM, Storage 등 모든 리소스는 **한국 리전(`Korea Central`, `Korea South`)** 에만 배포 가능하도록 정책 적용
