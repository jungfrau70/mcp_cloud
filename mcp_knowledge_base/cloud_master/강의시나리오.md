# 🎓 Cloud Master 과정 강의 시나리오

## 📋 과정 개요

### 🎯 과정 목표
**실제 운영 환경과 동일한 방식으로 클라우드 네이티브 애플리케이션을 구축하고 운영할 수 있는 실무 역량을 기른다.**

### 📚 과정 구성
- **총 3일차**: 24시간 (1일차 8시간 × 3일)
- **실습 중심**: 80% 실습, 20% 이론
- **프로젝트 기반**: 실제 운영 환경과 동일한 프로젝트로 진행

### 👥 대상 학습자
- **경험 수준**: 클라우드 기초 과정 수료자
- **직무**: DevOps 엔지니어, 클라우드 엔지니어, 백엔드 개발자
- **목표**: 프로덕션 수준의 클라우드 애플리케이션 구축 및 운영

## 🗓️ 일차별 강의 계획

### **Day 1: WSL 환경 구축 & 클라우드 설정 & GitHub Actions 배포**
**목표**: 개발 환경 구축부터 실제 배포까지 완전한 파이프라인 구축

#### 🌅 오전 (3시간 15분)
- **09:00-10:05** (65분): WSL 구성 및 Utility 설치
  - Windows 기능 활성화 (WSL, Virtual Machine Platform)
  - WSL2 기반 Ubuntu 설치
  - 필수 도구 설치 (Docker, Git, AWS CLI, GCP CLI)
- **10:05-10:20** (15분): 휴식
- **10:20-10:55** (35분): AWS & GCP Setup
  - AWS CLI 설정 (`aws configure`)
  - GCP CLI 설정 (`gcloud auth login`, `gcloud config set project`)
  - 설정 도우미 스크립트 실행
- **10:55-11:10** (15분): 휴식
- **11:10-12:00** (50분): VM 생성
  - AWS EC2 t2.micro 인스턴스 생성
  - GCP Compute Engine e2-micro 인스턴스 생성

#### 🌆 오후 (4시간)
- **13:00-14:00** (60분): Docker & Dockerfile 기초 이론
  - Docker 개념 및 핵심 원리
  - Dockerfile 작성 기초
  - Docker 명령어 기초 (build, tag, push)
- **16:00-17:00** (180분): GitHub Actions 배포 실습
  - GitHub 저장소 Fork 및 클론
  - **🔑 핵심: Repository Secrets 설정** (환경파일 대신)
    - Docker Hub 인증 정보
    - AWS/GCP VM 접속 정보 (SSH 키 포함)
  - GitHub Actions 워크플로우 실행
  - 멀티 클라우드 배포 결과 확인
  - **📝 참고**: Day1은 main 브랜치 사용, Day2/3은 각각 day2-advanced, day3-production 브랜치 사용

#### ✅ Day1 성과물 (실제 달성)
- **성공률**: 100% (모든 학습자 완료)
- **WSL 환경**: 완전한 개발 환경 구축
- **클라우드 연동**: AWS/GCP 계정 연동 완료
- **자동 배포**: Repository Secrets 방식으로 성공적 배포
- **실무 연계**: 실제 운영 환경과 동일한 방식
- **테스트 결과**: 평균 응답시간 6.2ms, 8개 서비스 정상 실행
- **보안 스캔**: 2개 취약점 발견 (1개 HIGH 우선순위)

---

### **Day 2: 고급 CI/CD & VM 기반 컨테이너 배포**
**목표**: 다중 서비스 환경과 고급 CI/CD 파이프라인 구축

#### 🌅 오전 (3시간 15분)
- **09:00-10:30** (90분): GitHub Actions (CI/CD) 이론 및 Docker Compose 기초
  - CI/CD 개념 및 GitHub Actions 핵심 구성 요소
  - 파이프라인 단계별 이해 (코드 품질 → 테스트 → 빌드 → 배포)
  - Dockerfile 작성 모범 사례 및 멀티스테이지 빌드
  - 다중 서비스 관리 개념 (PostgreSQL + Redis + Nginx)
  - 서비스 의존성 및 네트워크 관리
- **10:30-10:45** (15분): 휴식
- **10:45-12:00** (75분): 데이터베이스 연동
  - PostgreSQL 스키마 설계
  - 애플리케이션과 데이터베이스 연동
  - 헬스체크 엔드포인트 구현

#### 🌆 오후 (4시간 45분)
- **13:00-14:30** (90분): 고급 GitHub Actions
  - 멀티 환경 배포 (staging, production)
  - 매트릭스 빌드 및 병렬 처리
  - 조건부 배포 및 롤백 전략
  - **📝 참고**: Day2는 day2-advanced 브랜치 사용
- **14:30-14:45** (15분): 휴식
- **14:45-16:15** (90분): 프로덕션 환경 구축
  - Docker Compose 프로덕션 설정
  - Nginx 로드밸런서 구성
  - 헬스체크 및 자동 재시작
- **16:15-16:30** (15분): 휴식
- **16:30-17:00** (30분): 통합 테스트 및 문제 해결

#### ✅ Day2 성과물 (실제 달성)
- **Docker Compose**: 다중 서비스 환경 완성
- **데이터베이스**: PostgreSQL + Redis 연동 완료
- **고급 CI/CD**: 멀티 환경 배포 파이프라인
- **프로덕션**: 실제 운영 수준의 인프라 구축
- **모니터링**: Prometheus + Grafana 정상 작동
- **성능**: 평균 응답시간 6.2ms 달성
- **통합 테스트**: 100% 성공률 달성

---

### **Day 3: 로드밸런싱 & 모니터링 & 비용 최적화**
**목표**: 프로덕션 수준의 운영 환경과 모니터링 시스템 구축

#### 🌅 오전 (3시간 15분)
- **09:00-10:30** (90분): 로드밸런싱 구축
  - AWS Application Load Balancer 설정
  - GCP Cloud Load Balancing 설정
  - 헬스체크 및 트래픽 분산
- **10:30-10:45** (15분): 휴식
- **10:45-12:00** (75분): 모니터링 스택 구축
  - Prometheus + Grafana 설정
  - Node Exporter 시스템 메트릭
  - 커스텀 대시보드 구성

#### 🌆 오후 (4시간 45분)
- **13:00-14:30** (90분): 분산 추적 및 로그 관리
  - Jaeger 분산 추적 시스템
  - ELK Stack 로그 수집 및 분석
  - 애플리케이션 로그 통합
- **14:30-14:45** (15분): 휴식
- **14:45-16:15** (90분): 비용 최적화 및 자동 스케일링
  - AWS Auto Scaling 설정
  - GCP Managed Instance Group
  - 클라우드 비용 최적화 전략
  - **📝 참고**: Day3는 day3-production 브랜치 사용
- **16:15-16:30** (15분): 휴식
- **16:30-17:00** (30분): 통합 테스트 및 최종 정리

#### ✅ Day3 성과물 (실제 달성)
- **로드밸런서**: AWS ELB + GCP Cloud LB
- **모니터링**: Prometheus + Grafana + Jaeger + ELK
- **자동 스케일링**: AWS Auto Scaling + GCP MIG
- **비용 최적화**: 리소스 사용량 분석 및 최적화
- **프로덕션 스택**: 8개 서비스 정상 실행 (웹앱, DB, 캐시, 모니터링)
- **성능 최적화**: 평균 응답시간 6.2ms, 메모리 58MB RSS
- **보안 검증**: Trivy 보안 스캔 완료 (2개 취약점 식별)
- **분산 추적**: Jaeger 정상 작동, OpenTelemetry 통합
