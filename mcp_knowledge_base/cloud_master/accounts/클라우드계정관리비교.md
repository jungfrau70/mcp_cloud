이 문서는 Azure, AWS, GCP 세 클라우드 플랫폼의 계정 가입 및 권한 관리 방식을 비교 분석합니다.

- **보안 모범 사례 통합**

## 1️⃣ 계정 구조 비교

### Azure (Microsoft)
```
개인 Microsoft 계정 (MSA)
├── Azure 구독 (Subscription)
│   ├── Entra ID (Azure AD)
│   │   ├── itadmin@<tenant>.onmicrosoft.com
│   │   └── Global Administrator 역할
│   └── Azure 리소스
│       ├── Owner 역할
│       └── Billing Administrator 역할
```

### AWS
```
개인 이메일 계정
├── AWS 계정 (Root)
│   ├── IAM  (** Identity Manager 아님)
│   │   ├── itadmin (IAM 사용자)
│   │   └── AdministratorAccess 정책
│   │   └── AWSBillingConductorServiceRolePolicy, Billing, CostExplorerReadOnlyAccess 등) 정책책
│   └── AWS 리소스
│       ├── Billing 정책
│       └── CostExplorerServiceFullAccess 정책
```

주) 기본적으로 AWS 계정 root 외 IAM 사용자는 Billing 콘솔 접근 불가 --> 가이드 참조

### GCP
```
개인 Google 계정
├── GCP 프로젝트
│   ├── Cloud Identity / Google Workspace
│   │   ├── itadmin@<domain>.com
│   │   └── Owner 역할
│   └── GCP 리소스
│       ├── Billing Account Administrator
│       └── Cost Management Admin
```

1️⃣ IAM 사용자에게 Billing 권한 허용 필요

## 2️⃣ 권한 관리 방식 비교

### Azure RBAC vs AWS IAM vs GCP IAM

| 구분 | Azure | AWS | GCP |
|------|-------|-----|-----|
| **권한 모델** | RBAC (역할 기반) | IAM (정책 기반) | IAM (역할 기반) |
| **최상위 권한** | Global Administrator | Root 사용자 | 프로젝트 Owner |
| **리소스 권한** | Owner | AdministratorAccess | Owner |
| **비용 권한** | Billing Administrator | Billing + CostExplorer | Billing Account Administrator |

### 권한 할당 방식

#### Azure
```bash
# PowerShell
New-AzRoleAssignment -SignInName "itadmin@tenant.onmicrosoft.com" -RoleDefinitionName "Owner" -Scope "/subscriptions/subscriptionId"
```

#### AWS
```bash
# AWS CLI
aws iam attach-user-policy --user-name itadmin --policy-arn arn:aws:iam::aws:policy/AdministratorAccess
```

#### GCP
```bash
# gcloud CLI
gcloud projects add-iam-policy-binding PROJECT_ID --member="user:itadmin@domain.com" --role="roles/owner"
```

## 3️⃣ 계정 생성 과정 비교

### Azure 계정 생성
1. **개인 Microsoft 계정으로 Azure 가입**
2. **Entra ID에서 itadmin 사용자 생성**
3. **Global Administrator 역할 할당** (Entra ID 관리)
4. **Owner 역할 할당** (Azure 리소스 관리)
5. **Billing Administrator 역할 할당** (비용 관리)

### AWS 계정 생성
1. **개인 이메일로 AWS 계정 가입**
2. **IAM에서 itadmin 사용자 생성**
3. **AdministratorAccess 정책 연결** (AWS 서비스 관리)
4. **Billing 정책 연결** (비용 관리)
5. **CostExplorerServiceFullAccess 정책 연결** (비용 분석)

### GCP 계정 생성
1. **개인 Google 계정으로 GCP 가입**
2. **Cloud Identity/Google Workspace에서 itadmin 사용자 생성**
3. **Owner 역할 할당** (GCP 프로젝트 관리)
4. **Billing Account Administrator 역할 할당** (비용 관리)
5. **Cost Management Admin 역할 할당** (비용 최적화)

## 4️⃣ 보안 기능 비교

### 다중 인증 (MFA)

| 플랫폼 | MFA 방식 | 설정 위치 | 필수 여부 |
|--------|----------|-----------|-----------|
| **Azure** | SMS, 앱, 하드웨어 토큰 | Entra ID → 보안 | 권장 |

| **GCP** | SMS, 앱, 하드웨어 토큰 | Google 계정 → 보안 | 권장 |

### 액세스 키 관리

| 플랫폼 | 키 유형 | 생성 위치 | 보안 권장사항 |
|--------|---------|-----------|---------------|
| **Azure** | Service Principal | App registrations | 정기적 로테이션 |
| **AWS** | Access Key + Secret Key | IAM → 보안 자격 증명 | 정기적 로테이션 |
| **GCP** | Service Account Key | IAM → 서비스 계정 | 정기적 로테이션 |

## 6️⃣ 자동화 스크립트 비교

### Azure 자동화
```powershell
# PowerShell
New-AzRoleAssignment -SignInName "itadmin@tenant.onmicrosoft.com" -RoleDefinitionName "Owner" -Scope "/subscriptions/subscriptionId"
New-AzRoleAssignment -SignInName "itadmin@tenant.onmicrosoft.com" -RoleDefinitionName "Billing Administrator" -Scope "/subscriptions/subscriptionId"
```

### AWS 자동화
```bash
# AWS CLI
aws iam create-user --user-name itadmin
aws iam attach-user-policy --user-name itadmin --policy-arn arn:aws:iam::aws:policy/AdministratorAccess
aws iam attach-user-policy --user-name itadmin --policy-arn arn:aws:iam::aws:policy/Billing
```

### GCP 자동화
```bash
# gcloud CLI
gcloud projects add-iam-policy-binding PROJECT_ID --member="user:itadmin@domain.com" --role="roles/owner"
gcloud projects add-iam-policy-binding PROJECT_ID --member="user:itadmin@domain.com" --role="roles/billing.user"
```

## 7️⃣ 장단점 비교

### Azure
**장점:**
- Microsoft 생태계와 완벽 통합
- 엔터프라이즈급 보안 기능
- 세밀한 권한 제어

**단점:**
- 복잡한 권한 구조
- 학습 곡선이 가파름
- 비용이 상대적으로 높음

### AWS
**장점:**
- 가장 성숙한 클라우드 플랫폼
- 풍부한 서비스와 도구
- 강력한 자동화 기능

**단점:**
- 복잡한 서비스 구조
- 비용 예측이 어려움
- 초기 설정이 복잡

### GCP
**장점:**
- 간단하고 직관적인 인터페이스
- 강력한 데이터 분석 도구
- 유연한 가격 정책

**단점:**
- 상대적으로 적은 서비스
- 엔터프라이즈 기능 부족
- 지역별 서비스 가용성 차이

## 8️⃣ 선택 가이드

### Azure를 선택해야 하는 경우
- Microsoft 생태계 사용 중
- 엔터프라이즈급 보안이 중요
- Active Directory 통합 필요

### AWS를 선택해야 하는 경우
- 가장 많은 서비스가 필요
- 글로벌 서비스 운영
- 강력한 자동화가 중요

### GCP를 선택해야 하는 경우
- 데이터 분석이 중요
- 간단한 설정을 원함
- 비용 효율성이 중요

## 9️⃣ 통합 관리 전략

### 멀티클라우드 환경에서의 계정 관리

#### 공통 원칙
1. **최소 권한 원칙**: 필요한 최소한의 권한만 부여
2. **정기적 권한 검토**: 3-6개월마다 권한 검토
3. **MFA 필수**: 모든 관리자 계정에 MFA 설정
4. **액세스 로깅**: 모든 액세스 로그 기록 및 모니터링

#### 통합 도구
- **Terraform**: 인프라 코드화
- **Ansible**: 설정 관리 자동화
- **Pulumi**: 다중 언어 지원 인프라 코드
- **CloudFormation**: AWS 전용
- **Azure Resource Manager**: Azure 전용
- **Deployment Manager**: GCP 전용

## 🔟 보안 모범 사례

### 공통 보안 가이드라인

#### 계정 보안
1. **강력한 비밀번호**: 복잡하고 고유한 비밀번호 사용
2. **2단계 인증**: 모든 계정에 MFA 설정
3. **정기적 비밀번호 변경**: 3-6개월마다 변경
4. **비활성 계정 정리**: 사용하지 않는 계정 제거

#### 권한 관리
1. **역할 기반 접근 제어**: 사용자별 역할 정의
2. **최소 권한 원칙**: 필요한 최소한의 권한만 부여
3. **정기적 권한 검토**: 권한 사용 현황 모니터링
4. **임시 권한**: 필요시에만 임시 권한 부여

#### 모니터링
1. **액세스 로깅**: 모든 액세스 로그 기록
2. **비정상 활동 탐지**: 의심스러운 활동 모니터링
3. **정기적 감사**: 보안 상태 정기적 점검
4. **사고 대응**: 보안 사고 대응 계획 수립

## 📞 문제 해결

### 일반적인 문제 및 해결방법

#### 권한 관련 문제
1. **권한 부족**: 필요한 역할/정책 확인
2. **액세스 거부**: 계정 상태 및 권한 할당 확인
3. **서비스 접근 불가**: API 활성화 상태 확인

#### 계정 관련 문제
1. **로그인 실패**: 계정 상태 및 비밀번호 확인
2. **MFA 오류**: MFA 설정 및 백업 코드 확인
3. **키 만료**: 액세스 키 갱신
